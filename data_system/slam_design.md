

小车上装了前后两个摄像头，还有侧面的摄像头，要通过slam的方法简单判断小车是在前进还是后退，怎么实现？摄像头的标定信息是不知道的，不需要知道小车的前进后退具体的速度位置，只需要判断是在前进还是后退就行，如果需要标定，那么标定过程需要尽量q简单，怎么实现？


## 设计结论

这个需求不需要完整 SLAM，也不需要建图。使用“单目视觉里程计（VO）+ 多摄像头投票”即可。由于只判断运动方向，单目视觉无法获得真实尺度并不影响结果。

输出应设计成三种状态：

- 前进
- 后退
- 静止或无法判断

车辆静止、纯旋转、画面无纹理或者严重模糊时，视觉无法可靠地进行前进/后退二选一。

## 相邻帧运动方向恢复

每个摄像头独立处理：

1. 使用 ORB，或者 Shi-Tomasi + LK 光流提取和跟踪特征点。
2. 使用 RANSAC 去除错误匹配和动态物体上的异常点。
3. 根据相机内参计算本质矩阵并恢复相机运动：

```python
E, mask = cv2.findEssentialMat(p1, p2, K, method=cv2.RANSAC)
_, R, t, mask = cv2.recoverPose(E, p1, p2, K)
displacement = -R.T @ t
```

`displacement` 没有真实尺度，但其方向可用于判断车辆前进或后退。

将其与该摄像头坐标系下的车辆前进方向做点积：

```python
score = dot(normalize(displacement), forward_direction_camera)
```

- `score > threshold`：前进
- `score < -threshold`：后退
- 其他情况：无法判断

OpenCV 坐标变换的方向容易混淆，最终符号应通过一次已知前进测试确认。

## 简单标定流程

### 1. 相机内参标定

每个摄像头单独标定，不需要多个摄像头同时看到标定板：

1. 打印 ChArUco 或棋盘格标定板。
2. 每个摄像头从不同距离和角度拍摄约 15～30 张图片。
3. 使用 OpenCV `calibrateCamera`；鱼眼镜头使用 `fisheye.calibrate`。
4. 保存 `fx、fy、cx、cy` 和畸变参数。

非广角镜头可以先使用近似内参快速验证：

```text
cx = 图像宽度 / 2
cy = 图像高度 / 2
fx ≈ fy ≈ 0.8～1.2 × 图像宽度
```

近似内参可能足以判断方向，但广角和鱼眼镜头建议正式标定。

### 2. 自动学习车辆前进方向

不需要精确测量摄像头相对车体的外参：

1. 让小车沿直线明确前进 3～5 米。
2. 所有摄像头分别运行上述 VO。
3. 收集每个摄像头有效的 `displacement`。
4. 归一化后取中位数，得到每个摄像头的 `forward_direction_camera`。
5. 后退方向就是该方向的反方向。

这种方法可以自动适应前摄、后摄和侧摄的不同安装方向，也允许存在少量安装角度偏差。

## 多摄像头融合

每个摄像头输出方向分数和置信度：

```text
置信度 = RANSAC 内点数 × 内点比例 × 视差大小
总分 = Σ(摄像头分数 × 置信度) / Σ置信度
```

对结果进行约 0.5～1 秒的时间窗口平滑：

- 总分持续大于阈值：前进
- 总分持续小于负阈值：后退
- 视差太小、画面质量差或摄像头意见冲突：无法判断

侧面摄像头通常对直线前后运动最敏感；前后摄像头面对远距离场景时视差可能较小。

## 结果有效性检查

一帧 VO 结果建议至少满足：

- 有效匹配点大于约 50
- RANSAC 内点比例大于约 40%
- 中位视差大于 1～2 像素
- 画面没有严重模糊或被大面积动态物体遮挡
- 连续多帧判断结果基本一致

车辆原地转向时应输出“旋转或无法判断”。如果车辆具有 IMU，可以使用陀螺仪剔除纯旋转，可靠性会明显提高。

## 无标定备选方案

如果完全不做相机标定，可以记录一次已知前进的视频，为每个摄像头建立分块光流模板。运行时计算当前光流与模板的相关性：

- 与前进模板同向：前进
- 与前进模板反向：后退

这种方法实现最简单，但在转弯、动态物体较多或场景深度发生明显变化时，不如本质矩阵 VO 稳定。

## 推荐实施方案

采用“每个摄像头简单内参标定 + 已知前进 3～5 米自动学习方向 + 多帧、多摄像头加权投票”。该方案不需要完整 SLAM、不需要建图，也不需要摄像头之间的精确外参。
